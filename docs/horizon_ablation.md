# 想象长度H=16/32：源码审查与对照设计

**状态：计划与静态源码审查完成，GPU试验未运行；不能作为新的性能结论。**

## 1. 源码发现

在固定上游commit的 `allmimic/train.py::update_policy()` 中，策略loss为 `-mean(J)/H`，然后按 `cfg.pi_clip` 裁剪梯度范数。recommended preset把 `pi_clip` 设置为 `0.03125`，即1/32，而不是自动按H变化。

因此只把H从32改成16，会同时把相同J对应的loss/梯度放大2倍。保持原裁剪值时，未除以H的J梯度所对应上限为 `H*pi_clip`：H32是1，H16是0.5。即使Adam对整体梯度缩放通常近似不敏感，裁剪与epsilon也使其并非严格等价。不能直接把差异全部解释成长短想象的作用。

另外：

- J包含折扣奖励及 `gamma^H * survival * V(s_H)`，改变H会自然改变bootstrap位置与权重。
- critic每次优化器更新数为 `critic_epochs * critic_minibatches`；但数据量为 `pi_batch * H`，同样的batch起点数下H32有两倍想象样本。
- 奖励分项日志按H平均，`img_survival`是H末端软存活权重；不同H不能仅直接比较这两个日志就判定策略更好。
- `wm_err1/wm_errk`使用固定k=8，但误差归一化统计与采样分布会随训练改变；它们只能作为在线诊断，不能取代共同样本上的预测误差。
- `train_time`不含所有启动、评估和保存时间；总进程耗时必须另行记录。

## 2. 推荐的小规模首轮

| 条件 | H16 | H32 |
| :-- | --: | --: |
| seed | 0 | 0 |
| 真实并行环境数 | 4096 | 4096 |
| 迭代上限 | 8000 | 8000 |
| 策略起点batch | 4096 | 4096 |
| WM k / batch / batches | 8 / 2048 / 10 | 8 / 2048 / 10 |
| UTD | 0.4 | 0.4 |
| 策略loss数值除数 | **固定32** | **固定32** |
| 策略范数裁剪 | 1/32 | 1/32 |
| 每组独立初始化 | 是 | 是 |
| 评估间隔 | 2000次迭代 | 2000次迭代 |

主对照建议将两组的loss数值除数统一固定32，保留其余优化器设置。H32与原流程一致；H16需要在独立源码副本中做最小修改并记录文件哈希/差异。**这个修改尚未应用，也尚未通过真实梯度检查。**

不通过把H16的起点batch翻倍来补齐想象步数，因为那又改变策略蒙特卡洛起点数。固定起点batch时，critic样本量及想象计算量随H变化是本轮管线对照的组成部分，必须明确报告；它不是完全隔离所有内部中介变量的因果实验。

可以额外把“原生除H、clip=1/H”的设置作为敏感性检查，但不与固定除32的组混入同一主比较。本轮先不扩展实验矩阵。

## 3. 预算与记录

主口径采用**等真实仿真步数/等迭代**，不是两组各跑同样分钟数。另报告达到同一训练进度的耗时、吞吐和峰值显存，区分样本效率与计算效率。

两个H组必须在同一新实例、同GPU型号、同依赖版本及数据上完成。已有2小时H32结果只作历史背景，不充当8000次迭代新实验的配对基线。不能让H16在新卡跑，再用旧卡旧时长的H32作对照。

每组应保存：原始配置、代码/补丁哈希、依赖、seed、GPU/驱动、checkpoint、真实环境步、WM/策略更新数、累计训练耗时、总进程耗时、编译/预热耗时、评估耗时、GPU峰值显存和任何超时。达到安全时限但未完成8000次迭代的组不能标为已完成等步数对照。

## 4. 共同评估与模型误差

主指标为独立FP32完整40动作回报、失败数、逐项执行步数；不能用想象回报J或训练reset片段回报代替。

模型误差需要在**同一份固定诊断转移集合**上测量1/4/8/16步预测，使用记录的绝对setpoint动作、相同起点与相同物理上下文，报告物理单位及共同归一化标准。诊断集合可以从已归档的完整物理回放中固定抽取，但它不是未见动作测试集。相应独立模型评估脚本和上下文校验仍待实现，不能声称已具备该结果。

## 5. GPU启动前门槛

1. 独立源码副本与固定除数最小改动可追踪，不覆盖旧实验代码/输出。
