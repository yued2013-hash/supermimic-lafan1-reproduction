## 验证协议

每条动作从首帧执行到完整序列结束，确定性策略、固定评估条件，沿用实际源码的硬终止规则。归一化回报为该条动作实际奖励之和除以 `0.1 * (frames - 1)`，不是只除以已经执行的步数。报告平均回报和失败数，分别描述跟踪质量与是否提前终止。

这是训练库评估。未见动作、跨seed、实机迁移及不同物理参数下的泛化尚未验证。视频48秒，包含行走、舞蹈、跳跃、跌倒起身四段各前12秒；左侧运动学参考，右侧最终策略的物理仿真，25fps原速。录像只是展示，完整40条验收依据是JSON与逐项步数。

## 关键loss

| 项 | 实际含义 |
| :-- | :-- |
| wm_loss | 8步自回归预测的状态误差，经运行标准差归一化平方，使用recommended关节权重，跨8步求和，再对有效窗口平均 |
| wm_err1 / wm_errk | 第1/8步未加权的归一化误差诊断，不是物理单位 |
| pi_loss | `-mean(J)/32`；J包含折扣、存活加权奖励和末端critic估值 |
| v_loss | 对TD(lambda)目标的存活/有效性加权均方误差，日志平均critic各epoch/minibatch |
| img_survival | 想象轨迹软存活权重，不等同于40动作真实成功率 |

本实现没有学习的termination/BCE头。优化策略时冻结WM网络参数，梯度仍经过WM状态链回到策略；critic单独拟合。输入归一化和replay分布会变化，loss下降本身不能替代真实物理评估。

## 验证情况与不足

CPU pytest 6项通过，额外flags/goal-mode/WM梯度检查与64环境GPU物理测试通过。专门compiled-BPTT全量一致性测试在900秒上限超时，未通过完整验收。正式训练使用了BPTT，但不能据此替代该项检查。
